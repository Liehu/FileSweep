# FileSweep 产品定位与功能设计

**日期**：2026-06-22
**状态**：已批准（grill-me 讨论成果）

---

## 1. 核心定位

**面向开发者的软件文件瘦身工具**——把磁盘上的软件文件从"全量保留"科学降级为"按需保留"。

目标用户：开发者，装机多，软件/安装包/开发环境文件散乱堆积。

## 2. 核心闭环

```
扫描 → 分类 → AI 丰富 → 智能建议引擎 → 用户审核调整 → 批量执行（回收站+可回滚）
```

## 3. 智能建议引擎（核心差异化）

### 决策矩阵

| 条件 | 建议 | 置信度 | 默认勾选 |
|---|---|---|---|
| 绿色软件目录 | 保留 | — | 不出现 |
| 个人文档/照片/视频 | 保留 | — | 不出现 |
| 无官网入口 + 非绿色软件 | 保留 | — | 不出现 |
| 同软件旧版本 | 删除旧版 | 高 | ✅ |
| 完全重复（哈希） | 删除副本 | 高 | ✅ |
| 知名软件（内置表匹配）+ 官网入口 | 降级为链接 | 高 | ✅ |
| 非知名软件 + AI 补全官网入口 | 降级为链接 | 中 | ❌ |

### 「降级为链接」设计

- 删除文件，保留 catalog 记录（含官网入口、描述、版本）
- 官网入口级别（非具体下载 URI）→ 解决 URL 失效问题
- 删除走回收站 + operation_logs 可回滚

### 知名度数据（两者结合）

- 内置表：常见开发者软件映射（Python/Node/Git/VSCode...），离线可用
- AI 补充：长尾软件的 download_reliability 字段（high/medium/low）

### 呈现：摘要 → 分组 → 展开

```
摘要：150 个文件建议清理（预计释放 12.3 GB）
  ├── 高置信 80 个（8.5 GB）  [全部勾选] [执行]
  ├── 需确认 50 个（3.2 GB）  [展开查看]
  └── 旧版本 20 个（0.6 GB）  [全部勾选] [执行]

展开后支持：按类型分组 / 按路径分组
每条可手动调整建议（保留/降级/删除）
```

## 4. 与其他插件的关系

| 插件 | 职责 | 数据关系 |
|---|---|---|
| filesweep（本项目） | 文件瘦身 | 核心 |
| appmover（第二个插件） | 新机装机/环境迁移 | 读 filesweep 的 catalog |
| 搜索 | 依赖 Everything SDK | 不重复造轮子 |
| 内容去重 | 不做（Czkawka 优秀） | — |

## 5. 架构原则

- 插件化避免未来重构，但不过度抽象——第二个插件落地时再调整 Plugin trait
- 聚焦 filesweep 功能闭环，不急着做平台
- 配置 DB 化进行中（4 张表已建，CRUD + UI 待完成）
